# Header Detection Specification (QF2)

## 目標

在報價單欄位位置不固定的情境下，先把「表頭」解析成一致的欄位對照（`header_map`），再把每列資料對齊到 `RawQuoteRow`。  
此規格只定義核心邏輯，不進行大量真實檔案解析。

## 一、基本原則

1. 不能假設欄位位置固定。
2. 系統需先掃描每頁可能的表頭列。
3. 對每個表頭儲存「欄位名稱 → 欄位角色」的 `header_map`，並可持有多個候選欄位與信心分數。
4. 當無法穩定辨識必要欄位時，整份文件進入 `review_queue`，不進行自動轉入候選行輸出。

## 二、掃描策略

- 規則式掃描上、下游 3~6 列作為候選表頭行；先比對明顯表頭詞彙，再比對局部含義（例如單位欄位經常為「單位」或「單位/工料」）。
- 逐欄判斷 token 相似度與關鍵字命中，得到欄位角色候選：
  - `item_name`
  - `unit`
  - `quantity`
  - `unit_price`
  - `amount`
  - `note`
- 同欄可命中多角色時，保留最高分角色並寫入 `header_map.alternatives` 以利人工盤點。
- `header_map` 儲存欄位範圍：
  - `source`: `text` / `merged` / `empty`
  - `cell_index`: 欄位索引
  - `confidence`: 0~1

## 三、同義表頭（synonyms）

以下為預設同義集，必須支援至少以下映射：

- 項目名稱類：
  - `品名`, `工程項目`, `項目名稱`, `施工項目`, `項目`
- 單位類：
  - `單位`
- 數量類：
  - `數量`, `數量小計`
- 價格類：
  - `單價`, `估價單價`
- 金額類：
  - `金額`, `複價`, `小計`
- 備註類：
  - `備註`, `說明`, `規格`

同義表頭需同時考慮：
- 全型/半型符號差異
- 當行文字含括號（例如 `品名(說明)`）時，仍可判為該欄位
- 常見縮寫：`數`, `單`, `金`, `備`

## 四、必要欄位與缺欄位行為

建議的必要欄位至少一組：
- `item_name` 或 `note`（若同時缺失，無法形成可用行）
- `quantity` 或 `amount`（任一可接受，缺一不可全缺）
- `unit`（缺失可以先保留 `unit_raw` 空值，但需寫 warning）

缺少以下欄位時，該檔進 review_queue：
- 無法建立 `header_map` 的欄位角色至少 2 個
- `item_name` 欄位完全缺失
- `amount`/`unit_price`/`quantity` 全部缺失且行數超過最低可辨識門檻

## 五、行別排除規則

以下列型資料不得視為 quote line，也不建立 `RawCatalogItem`：
- 小計
- 合計
- 工程分類標題列

這些列可保留 row metadata，但 `row_role` 固定：
- `subtotal`
- `total`
- `trade_category_header`

對應欄位需仍進行欄位掃描與上下文保留，但不納入正常工項輸出。

## 六、Review Queue 觸發

以下情況需要 review_queue：
- 必要欄位缺失
- 欄位命中衝突（例如同一欄同時命中 `unit` 與 `quantity`）
- 多個表頭列互斥衝突且無法決議
- 出現不明表頭 token（例如非中文、無法切分、密集符號）
- `row_role` 無法可靠判斷且行內容含金額
